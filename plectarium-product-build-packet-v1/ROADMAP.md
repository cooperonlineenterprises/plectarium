# Plectarium Roadmap

**Status:** Dependency-aware product plan; not implementation authority

## S0 — Constitution and family pin

Validate product authority, source ownership, family lock, schemas, and claim
gates before code-bearing work.

## S1 — Foundational contracts

Implement strict schema/version handling, identity/tenancy, catalog,
plan/approval, job, runner, result, provenance, compatibility, and BOM
contracts with positive and adversarial fixtures.

## S2 — Minimum Complete Control Plane

Prove one vertical path from exact catalog discovery through capability plan,
approval, lease, execution, durable result, and truthful completion. Then prove
denial, cancellation, duplication, timeout, partial upload, and orphan recovery.

This is an integration checkpoint, not the final product.

## S3 — Cohesive experience and deployment modes

Build API/event/suite-CLI projections, the web application, direct/local mode,
hosted/private runners, customer-controlled operation, and air-gapped
export/import while preserving semantic and authority equivalence.

## S4 — Production hardening

Complete privacy/retention, audit, observability, measured SLOs, migrations,
backup/restore, tenant and runner adversarial testing, resilience, accessibility,
performance, and operations exercises.

## S5 — Mature v1 release

Produce reproducible distributions, SBOM, provenance, exact suite BOM, current
gate evidence, supported-version policy, and owner-approved release record.

No stage authorizes implementation merely by being listed here.
